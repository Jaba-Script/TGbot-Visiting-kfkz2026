# 📊 Бот відвідуваності

Telegram-бот для відмічання відсутніх студентів на парах з автоматичним записом у Google Таблиці.

---

## 🗂 Структура проєкту

```
attendance_bot/
├── credentials.json   # ключ сервісного акаунту Google (не публікувати!)
├── .env               # токен бота і налаштування
├── requirements.txt   # залежності Python
├── config.py          # завантаження змінних середовища
├── sheets.py          # робота з Google Таблицями
├── keyboards.py       # інлайн-клавіатури
├── states.py          # FSM-стани діалогу
├── handlers.py        # логіка бота
└── main.py            # точка входу
```

---

## ⚙️ Налаштування

### 1. Клонуй або скачай проєкт

### 2. Встанови залежності
```bash
pip install -r requirements.txt
```

### 3. Створи файл `.env`
Скопіюй `.env.example` → `.env` і заповни:
```
BOT_TOKEN=токен_від_BotFather
SPREADSHEET_ID=id_таблиці_з_посилання
ALLOWED_USERS=123456789
CREDENTIALS_FILE=credentials.json
```

> **SPREADSHEET_ID** — тільки ID з посилання, без `/edit?...`  
> Приклад: `docs.google.com/spreadsheets/d/`**ЦЕЙ_РЯДОК**/edit  
> **ALLOWED_USERS** — Telegram ID відповідальної особи (дізнатись через @userinfobot)

### 4. Налаштуй Google Таблицю

Таблиця повинна мати такі листи (назви точно як тут):

#### `Schedule` — розклад
| Пара | Пн | Вт | Ср | Чт | Пт |
|------|----|----|----|----|-----|
| 1    | Математика | — | Фізика | Математика | Історія |
| 2    | Фізика | Англійська | — | Англійська | Математика |

Порожня клітинка або `—` означає що пари немає.  
Використовуй **перевірку даних** (Data validation → Dropdown) для назв предметів, щоб уникнути опечаток.

#### `Студенти` — список групи
| Студент |
|---------|
| Іваненко Олексій |
| Петренко Марія |
| ... |

#### `Log` — журнал (бот пише сюди)
| Дата | День | Пара | Предмет | Студент | Статус | Відмітив | Час |
|------|------|------|---------|---------|--------|----------|-----|

Перший рядок — заголовки, решта заповнює бот автоматично.

#### Листи по предметах + загальний
Формули для цих листів додаються окремо після запуску бота.

### 5. Дай доступ сервісному акаунту
Відкрий `credentials.json` → знайди `client_email` → розшар таблицю на цей email як **Редактор**.

| Команда | Дія |
|---------|-----|

## 🔄 Сценарій відмічання

1. Відправ `/mark`
2. Бот покаже пари на сьогодні з розкладу
3. Обери потрібну пару
4. Натискай на імена відсутніх студентів (✅ → ❌)
5. Натисни **Підтвердити** — дані запишуться в `Log`

## 📊 Зведена таблиця відвідуваності

Лист **«Зведена»** — рядки: студенти, стовпці: робочі дні навчального року.  
Значення в кожній клітинці — кількість пропущених годин за цей день (1 пара = 2 год).

Структура стовпців:
- дати вересня → **Вересень** (місячний підсумок)
- дати жовтня → **Жовтень**
- ... → **Грудень** → **Січень** → **1 Семестр**
- дати лютого → ... → **Червень** → **2 Семестр** → **Разом**

Підсумкові колонки виділені жирним. Нулі приховані — клітинка порожня якщо пропусків немає.

Обидва листи створюються скриптами (бот туди нічого не пише, все рахується формулами з Log):

```bash
python setup_summary.py    # лист «Зведена» — всі предмети разом
python setup_subjects.py   # окремий лист на кожен предмет з розкладу
```

Перед запуском перевір дати навчального року у верхній частині файлу `setup_summary.py`:
```python
YEAR_START = date(2026, 9, 1)   # початок навчального року
YEAR_END   = date(2027, 6, 30)  # кінець навчального року
```

## 🧪 Тестові дані

Щоб перевірити що зведена таблиця рахує правильно — заповни Log тестовими даними:

```bash
python test_data.py          # додати тестові рядки
python test_data.py --clear  # очистити Log
```

Перед запуском відредагуй імена студентів у `TEST_ABSENCES` всередині `test_data.py` —  
вони мають точно збігатися з іменами в листі «Студенти».

## 🛡 Надійність

- **Захист від подвійної відмітки** — якщо пара вже відмічена, бот попереджає і питає підтвердження перед перезаписом.
- **Виправлення помилок** — `/edit` показує 15 останніх записів журналу, можна видалити будь-який одним тапом.
- **Обробка помилок** — всі запити до Google Sheets загорнуті в try/except, бот повідомляє про проблему замість того щоб мовчки впасти.

## 🔄 Чергування тижнів А/Б

Якщо розклад змінюється кожен тиждень, переведи лист **Schedule** у новий формат:

| Тиждень | Пара | Пн | Вт | Ср | Чт | Пт |
|---------|------|----|----|----|----|-----|
| А | 1 | Фізика | | Математика | | |
| А | 2 | | Хімія | | Біологія | |
| Б | 1 | Математика | | Фізика | | |
| Б | 2 | | Біологія | | Хімія | |

Перший рядок повинен починатись зі слова **«Тиждень»** — по цьому бот визначає формат.

Потім вкажи дату будь-якого **понеділка тижня А** у `.env`:
```
WEEK_A_START=01.09.2026
```

Бот автоматично визначає тип поточного тижня і показує відповідний розклад.  
Якщо `WEEK_A_START` не вказано — розклад вважається однаковим щотижня (старий формат).

## 🛡 Надійність (деталі реалізації)

**Retry для Sheets API** (`retry.py`) — всі звернення до Google Sheets загорнуті в декоратор `@with_retry`. При помилках 429/500/503 або обриві мережі — автоматичний повтор з експоненційною затримкою (5с → 10с → 20с).

**Логування в файл** — всі події записуються в `bot.log` (ротація: 5 МБ × 3 файли). Корисно при деплої на Render де консоль не завжди доступна.

**Протухлі кнопки** — якщо бот перезапустився поки хтось був в середині відмічання, старі кнопки не ламають бота а показують зрозуміле повідомлення.

**Команда `/status`** — перевіряє підключення до таблиці і наявність всіх потрібних листів.
